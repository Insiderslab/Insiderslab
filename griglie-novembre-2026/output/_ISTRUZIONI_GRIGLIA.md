# Come si scrive una griglia S3 (novembre 2026)

Due file per cliente in `output/`:
- `<Cliente>_GRILLA_INTERNA.md` — per il team
- `<Cliente>_PIANO_CLIENTE.md` — per il cliente

## Fonti
1. Il brief del cliente in `brief/<Cliente>.md` (già verificato: comanda lui).
2. La mappa media del cliente su Drive (CSV, separatore `;`, 14 colonne). Leggila con `mcp__Google_Drive__read_file_content`.
3. Numero e tipo di pezzi: **esattamente quelli del MASTER** riportati nel brief. Se il brief segnala un conflitto, usa il MASTER e scrivilo nelle note.

## Regole
- Una riga = un pezzo. Date distribuite nel mese, giorni feriali salvo motivo.
- Niente materiale già pubblicato, niente post vecchi riciclati. Nella mappa "già pubblicata" è "non so" ovunque: scegli comunque, ma scrivi nella colonna 16 "verificare che non sia già uscito".
- Ogni riga ha 1–3 file dalla mappa (nome file + link o percorso della colonna 2), oppure "DA CHIEDERE AL CLIENTE: <cosa>".
- Mai usare file con tag vietati (es. "NON usare", "soggetto vietato", "dottore visibile", "stock", "nome vecchio", "grafica 2025"). File con persone riconoscibili: consentiti ma con nota "verificare consenso".
- Niente prezzi, cifre, premi, recensioni, servizi o eventi non presenti nel brief.
- Italiano corretto, tono del brief. Nessuna parola vietata del cliente.
- Brief per Arianna e per Abraham in **spagnolo**, pratici, realizzabili senza domande. Testi a schermo in italiano.
- Piano per il cliente: solo italiano, niente spagnolo, niente note interne, niente nomi del team.
